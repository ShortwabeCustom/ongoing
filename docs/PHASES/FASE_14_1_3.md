## Bug Encontrado & Corregido

### Problema Crítico

Offset de timezone tenía el **signo invertido**:

```typescript
// ❌ INCORRECTO (Session anterior)
const adjustedDate = new Date(midnightUTC.getTime() - offset)

// ✅ CORRECTO (Esta sesión)
const adjustedDate = new Date(midnightUTC.getTime() + offset)
```

### Semántica

```
offset = UTC_time - tz_time

Para UTC-6 (Mexico): offset = +6 horas (UTC está 6 horas ADELANTE)

Para convertir midnight en tz a UTC:
  midnight_utc = midnight_tz + offset
  
Ejemplo:
  2026-08-12 00:00 México (UTC-6) + 6h = 2026-08-12 06:00 UTC ✅
```

### Impacto

Sin esta corrección:
- Rango de fechas completamente invertido
- Si usuario estaba en timezone ≠ México, resultados incorrectos
- Custom date ranges no matcheaban presets

## Rango UTC Correcto (México)

**Ejemplo REAL generado por código**:

```
Fecha calendario: 2026-08-12
Timezone: America/Mexico_City (UTC-6)

Conversión a UTC:
  00:00 en México = 06:00 UTC (suma +6h)
  23:59:59.999 en México = 05:59:59.999 UTC (del día siguiente)

Resultado final:
  dateFrom: 2026-08-12T06:00:00.000Z
  dateTo:   2026-08-13T05:59:59.999Z
  
Duración: 24 horas exactas (sin gaps, sin overlaps)
```
