## 📋 Resumen Ejecutivo

FASE 14.1.3 completa y hardena Date Intelligence asegurando que:

1. **Browser Back/Forward funciona**: URL y React state siempre sincronizados
2. **Timezone México**: "Hoy" = día local en México (no UTC)
3. **URL es fuente de verdad**: Cambios de URL (navegación browser) actualizan state
4. **router.push() estratégico**: Acciones explícitas crean historial navegable

| Aspecto | Anterior (14.1.2) | Ahora (14.1.3) |
|---------|-------------------|----------------|
| **Hydration** | Solo mount | Reactive a URL |
| **Back/Forward** | Broken (replace) | Funciona (push) |
| **Timezone** | UTC para todo | America/Mexico_City para presets |
| **URL Validation** | None | Enum + date format checking |

## 🎯 Problemas Resueltos

### Problema A — One-Time Hydration

**Antes**:
```typescript
useEffect(() => {
  if (hasFilters) { setAdvancedFilters(...) }
}, [])  // ← Empty: solo on mount
```
Browser back/forward → URL cambia → State NO se actualiza → UI desincronizada

**Después**:
```typescript
useEffect(() => {
  if (hasFilters) { setAdvancedFilters(...) }
}, [urlFilters])  // ← Reactive to URL changes
```
Browser back/forward → URL cambia → useUrlSync re-calcula → State actualiza → UI sincronizada

### Problema B — router.replace() sin historial

**Antes**:
```typescript
router.replace(newUrl)  // No history entry
```
Documented: "Back/Forward funciona"  
Reality: `replace()` no crea entries → Back/Forward imposible

**Después**:
```typescript
router.push(newUrl)  // History entry created
```
Ahora:
- Aplicar filtro → `push()` → history entry
- Limpiar filtros → `push()` → history entry
- Usuario puede hacer back/forward

### Problema C — Timezone UTC para usuarios en México

**Antes**:
```typescript
const nowUtc = new Date()  // UTC
const start = nowUtc.toISOString().split('T')[0]  // 2026-08-14 if 02:30 UTC
// User in Mexico at 20:30 (2026-08-13) gets 2026-08-14
```

User en México 20:30 local (02:30 UTC siguiente) → "Hoy" = mañana ❌

**Después**:
```typescript
const today = getTodayInTimezone('America/Mexico_City')
// Uses Intl.DateTimeFormat to calculate date in Mexico TZ
// 20:30 local → date = 2026-08-13
const start = formatDayStartAsUTC(today)  // 2026-08-13T06:00:00Z (midnight Mexico = 6am UTC)
```

User en México 20:30 local → "Hoy" = 2026-08-13 ✅

### Problema D — Sin validación de URL params

**Antes**:
```
/findings?dateType=foobar&dateFrom=invalid
→ State: { dateType: 'foobar', dateFrom: 'invalid' }
```

**Después**:
```typescript
const VALID_DATE_TYPES = ['created', 'updated', 'imported', 'session']
function isValidDateType(value): boolean { ... }
function isValidISODateTime(dateString): boolean { ... }

// If invalid, set to undefined (ignore bad param)
dateType: isValidDateType(dateType) ? dateType : undefined
```

## 🏗️ Arquitectura Implementada

### 1. Timezone Module (`lib/utils/timezone.ts`)

```typescript
export function getTodayInTimezone(tz: string = 'America/Mexico_City'): Date
// Uses Intl.DateTimeFormat to get date in timezone (not UTC)

export function formatDayStartAsUTC(localDate: Date): string
// Converts local date to UTC ISO for API: 2026-08-13 → 2026-08-13T06:00:00Z (for Mexico)

export function isValidISODateTime(dateString: string): boolean
// Validates ISO datetime format

export function isValidDateString(dateString: string): boolean
// Validates YYYY-MM-DD format
```

**Why Intl.DateTimeFormat**: 
- Native in all browsers (no library)
- Handles daylight saving time correctly
- Future-proof (if Mexico TZ rules change, built-in)
- No hardcoded offsets (UTC-6 would break in DST)

### 2. DatePresetButtons Refactored

**Before**:
```typescript
const nowUtc = new Date()
yesterday.setUTCDate(yesterday.getUTCDate() - 1)  // UTC math
```

**After**:
```typescript
const today = getTodayInTimezone('America/Mexico_City')
yesterday.setDate(yesterday.getDate() - 1)  // Local math on local date
const start = formatDayStartAsUTC(yesterday)  // Convert to UTC for API
```

**Result**:
```
"Hoy"       → 2026-08-13 Mexico (06:00 UTC - 05:59 UTC next day)
"Ayer"      → 2026-08-12 Mexico
"7 días"    → Last 7 days in Mexico timezone
"30 días"   → Last 30 days in Mexico timezone
```

### 3. useUrlSync Enhanced

**Changes**:
- Added `isValidDateType()` and `isValidISODateTime()` validators
- Changed `initialFilters` from function to `useMemo` value
- Changed `router.replace()` → `router.push()` in both `syncToUrl()` and `clearUrl()`
- Handle `searchParams.get()` null values (convert to undefined)

**Result**:
```
syncToUrl()  → router.push()  → Creates history entry
clearUrl()   → router.push()  → Creates history entry
Back/Forward works!
```

### 4. SearchFindings Reactive Hydration

**Before**:
```typescript
useEffect(() => {
  if (hasFilters) { setAdvancedFilters(...) }
}, [])  // Only on mount
```

**After**:
```typescript
useEffect(() => {
  if (hasFilters) { setAdvancedFilters(...) }
}, [urlFilters])  // On every URL change
```

**Result**:
```
User clicks browser Back
  → URL changes
  → useSearchParams() updates
  → useUrlSync recalculates initialFilters (memoized with [searchParams])
  → useEffect dependency [urlFilters] triggers
  → setAdvancedFilters() updates state
  → UI renders correct filters
```

```
Forward → /findings?dateType=imported&... ✅
```

### Timezone Conversion Example

User in Mexico City: **2026-08-13 20:30 local** (UTC-6)

```typescript
// Frontend calculation
const today = getTodayInTimezone('America/Mexico_City')
// today = Date object representing 2026-08-13 00:00 in Mexico timezone

const start = formatDayStartAsUTC(today)
// start = "2026-08-13T06:00:00.000Z" (midnight Mexico = 6am UTC)

const end = formatDayEndAsUTC(today)
// end = "2026-08-13T23:59:59.999Z" (last second Mexico = 5:59am next UTC)

// API request
GET /api/search/findings?dateType=created&dateFrom=2026-08-13T06:00:00.000Z&dateTo=2026-08-13T23:59:59.999Z

// Backend (PostgreSQL UTC)
SELECT * FROM findings
WHERE createdAt >= '2026-08-13T06:00:00Z' AND createdAt <= '2026-08-13T23:59:59Z'
// Returns findings created between midnight and 23:59 Mexico time ✅
```
